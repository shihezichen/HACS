# 临时共享区（tmp box）设计与契约 v1

> 刚哥 2026-09-20 规格：开一个临时区域，提供接口，用于各 Agent 交互时共享信息的存放与读取。
> Agent 之间只传简短信息 + 共享信息 id。id 带**读计数**：读满限定次数即销毁；超过限定时长无人读够也自动销毁。
>
> 本文件是实现的唯一依据（契约冻结）。实现方**不许自行改路径名、字段名、语义**。

## 0. 一句话

`POST /tmp` 存长文本 → 得到一个短 id → 把 `{摘要, tmp_id}` 塞进 A2A/NATS 载荷发给队友 →
队友 `GET /tmp/<id>` 取全文 → 取够 N 次（或过期）→ 正文自动销毁，行留痕。

## 1. 落点

- 宿主：**`blackboard_svc`（9940）进程内**新增路由，不新起服务、不新占端口。
  - 理由：复用现成的 `_auth_peer()` 鉴权、PG 连接池、日志、systemd 单元；省一个端口/单元。
  - `/tmp` **不在** `_is_shared_path()` 的匹配范围内，因此不会被 `_reject_write()` 的 405 拦住。
- 库：同一个 PG（龙虾 `127.0.0.1:9950` / `dbname=blackboard`），新表 `tmp_shared`。
- 该区与"共享内容平面"（`shared_content`）、黑板（`entries`）、会议（`roundtable_*`）**三套互不相干**，不掺字段。

## 2. 表结构（`sql/tmp_shared_schema.sql`，幂等可重复执行）

```sql
CREATE TABLE IF NOT EXISTS tmp_shared (
  tmp_id         text        PRIMARY KEY,        -- 't-' + 8 字符 base32 (A-Z2-7)，短到能塞进载荷
  owner          text        NOT NULL,           -- 写入者 = 鉴权结果（防冒名）
  audience       text[]      NOT NULL DEFAULT '{}',  -- 收件人成员名；空数组 = 仅 owner 可取
  title          text,                           -- 可选，便于列表排查
  body           text        NOT NULL,           -- 正文
  bytes          integer     NOT NULL,           -- 正文 UTF-8 字节数
  digest         text        NOT NULL,           -- 正文 sha256，去重用
  reads_max      integer     NOT NULL,           -- 读满销毁阈值 1..100
  reads_count    integer     NOT NULL DEFAULT 0, -- 已读**人数**（distinct reader）
  readers        text[]      NOT NULL DEFAULT '{}', -- 已读成员（去重依据 + 可审计）
  expires_at     timestamptz NOT NULL,           -- 按时长销毁
  created_at     timestamptz NOT NULL DEFAULT now(),
  destroyed_at   timestamptz,                    -- 销毁时间（正文已清空）
  destroy_reason text                            -- read_quota|expired|capacity|owner|schema
);
CREATE INDEX IF NOT EXISTS tmp_shared_expires ON tmp_shared (expires_at) WHERE destroyed_at IS NULL;
CREATE INDEX IF NOT EXISTS tmp_shared_owner   ON tmp_shared (owner, created_at DESC);
CREATE INDEX IF NOT EXISTS tmp_shared_digest  ON tmp_shared (digest) WHERE destroyed_at IS NULL;
```

**守卫触发器（照 `shared_content_schema.sql` 的纪律，数据库层拒绝，不靠应用层约定）：**

1. `tmp_id / owner / created_at / reads_max / expires_at / bytes / digest` **不可变**（UPDATE 改这些直接 RAISE）。
2. `body` **只允许一次单向清空**：`OLD.body = '' OR NEW.body = ''` 之外，不许 UPDATE 正文（防"读完之后偷偷改内容"）。
3. `DELETE` / `TRUNCATE` **一律拒**（销毁 = `destroyed_at` + `body=''`，行保留 → 留痕才成立）。
4. `reads_count` / `readers` 只许**单调增**（不许回退）。

**销毁语义（沿用共享内容平面）：销毁 ≠ 删行**。
`destroyed_at` 落时间 + `destroy_reason` + `body` 置空。谁写的、谁读过、为什么销毁，全部查得到。

## 3. 接口契约（svc 原生路径不带 `/api` 前缀，与 `/entries` `/search` `/sessions` 一致）

鉴权：一律 `Authorization: Bearer <成员token>`，`_auth_peer()` 口径不变。**author / reader 一律取鉴权结果**，请求体里传什么都不认。

### 3.1 写 `POST /tmp`

请求体：
```json
{"body": "<长文本>",
 "to": ["lobster","top001","quantum"],   // 收件人成员名；缺省 [] = 只有自己可取
 "reads": 3,                              // 可选，读满销毁阈值；缺省 = len(to)（不足 1 则 1）
 "ttl_s": 7200,                           // 可选，存活秒数；缺省 7200
 "title": "川西行程素材"}                  // 可选
```
成功 `200`：
```json
{"ok": true, "tmp_id": "t-7KQ3M2XA",
 "expires_at": "2026-09-20T13:25:00Z", "reads_max": 3, "bytes": 184320}
```

拒绝口径：
| 情况 | 码 | error |
|---|---|---|
| 无/错 token | 401 | `unauthorized` |
| body 非 JSON 对象 / `body` 空 / `to` 里含未知成员名 | 400 | `bad_request` |
| `body` 字节数 > 262144（256 KiB，与通信面齐平） | 413 | `payload_too_large` |
| `reads` 不在 1..100 / `ttl_s` 不在 60..86400 | 400 | `bad_request` |
| owner 活跃条数已达 200 | 429 | `quota_exceeded` |

### 3.2 读 `GET /tmp/<id>`

成功 `200`：
```json
{"ok": true, "tmp_id": "t-7KQ3M2XA", "title": "川西行程素材",
 "body": "<全文>", "bytes": 184320,
 "reads_count": 2, "reads_max": 3, "reads_left": 1,
 "repeat": false,          // true = 这个 reader 之前读过，本次不计数
 "destroyed": false,       // true = 本次是最后一次读，本条已在该请求内销毁（正文照给）
 "expires_at": "..."}
```
口径：
| 情况 | 码 | 说明 |
|---|---|---|
| 无/错 token | 401 | `unauthorized` |
| id 不存在 | 404 | `not_found` |
| **不属于 `audience` 且不是 owner** | **403** | `forbidden`（403 比 404 诚实：东西在，不给你） |
| 已销毁 | 410 | `gone`（`destroy_reason` 一并返回，便于调用方知道是读满还是过期） |
| 已过期但未扫到 | 410 | 同一个请求内**顺手销毁**，`destroy_reason='expired'` |

**读计数口径（关键，别改成"每次请求算一次"）：按 distinct reader 去重。**
- 理由：群发场景是"一份材料给 N 个成员各读一次"。若按请求计数，任一成员重试/刷新就吃掉一次配额 → **提前销毁**，是 bug。
- 同一 reader 重读：返回全文，`reads_count` 不增，`repeat=true`。
- **读满即销毁，但最后一次的正文要照给**：第 N 个不同 reader 读到时，先把正文返回，**同一事务内** `destroyed_at=now(), destroy_reason='read_quota', body=''`；响应带 `"destroyed": true`。

### 3.3 列表 `GET /tmp`

查询参数：`mine=1`（我写的）/ `inbox=1`（发给我的，未销毁且未过期）/ 缺省 = 两者合并；`limit`（1..50，默认 20）。
返回元数据**不含正文**（列表不吐内容，省流量、也防误扩大读取面）。

### 3.4 主动销毁 `DELETE /tmp/<id>`

仅 owner 可调（他人 403）。`200 {"ok":true,"destroyed_at":...,"destroy_reason":"owner"}`；已销毁则幂等 200。

## 4. 销毁的执行者（两道路）

1. **读时懒判 + 读满即时销毁**（主路径，见 3.2）—— 保证"读满就释放"是即时的，不等扫描。
2. **服务内 sweep 线程**（兜底）：9940 进程内一个 daemon 线程，**每 300s** 执行一次
   ```sql
   UPDATE tmp_shared SET body='', destroyed_at=now(), destroy_reason='expired'
    WHERE destroyed_at IS NULL AND expires_at <= now();
   ```
   选服务内线程而非新增 systemd timer：自包含、不新增部署单元、与服务同生命周期。
   最近一次 sweep 时间暴露在 `/healthz` 的 `tmp_swept_at` 字段。
3. **容量兜底**：全局活跃（未销毁）条数 > 5000 时，按 `expires_at` 最早优先销毁，`destroy_reason='capacity'`。

## 5. 与通信面的接合（第二阶段，本次只落接口）

- 载荷字段：`shared_ref = {"tmp_id": "...", "bytes": N, "sha256": "..."}`，`text` 只放摘要。
- 阈值：正文 > **8 KiB** 自动外置；收件侧见 `shared_ref` 自动 `GET /tmp/<id>` 取全文再喂 CLI。
- 纪律：**引用取不到内容必须显式报错**，不许静默降级成"只剩摘要"（那等于丢内容）。
- 成员侧只准有 `team.py` + `nats_client.py` 两个文件 → 外置/回取逻辑必须落在这两处，加 `team.py put/get` 子命令。

## 6. 验收矩阵（必须真跑，缺一条不算完）

| # | 动作 | 判据 |
|---|---|---|
| 1 | 建表 | `\d tmp_shared` 五列俱全；重复执行幂等不报错 |
| 2 | 触发器 | 手工 `UPDATE tmp_shared SET reads_max=99` 被拒；`DELETE` 被拒；`body` 二次改写被拒 |
| 3 | 写 | `POST /tmp` → 200 + 24 位内短 id |
| 4 | 非收件人读 | 第三人 `GET` → **403** |
| 5 | 按人计数 | 同一 reader 连读 3 次 → `reads_count` 恒为 1、`repeat=true` |
| 6 | 读满销毁 | 3 个不同成员各读 1 次 → 第 3 次响应 `destroyed=true`；随后 `GET` → **410** `destroy_reason=read_quota`；库里 `body=''` 且 `destroyed_at` 非空 |
| 7 | 过期销毁 | `ttl_s=60` 写入，等到点后 `GET` → **410** `destroy_reason=expired`；不等扫描也即时销毁 |
| 8 | sweep | sweep 跑过后，人为把某条 `expires_at` 改成过去 → 300s 内该条被销毁；`/healthz` 有 `tmp_swept_at` |
| 9 | 大小上限 | 262145 字节正文 → **413** |
| 10 | 超额 | 同一 owner 连写 201 条 → 第 201 条 **429** |
| 11 | **回归** | 黑板原端点 `/entries`（GET/POST）、`/search`、`/sessions`、`/tracking` 全部行为不变；看板 `9941/9942` 仍 200；`Publish Violation` 无新增 |

## 7. 部署

- DDL：`ssh lobster` 后 `psql "host=127.0.0.1 port=9950 dbname=blackboard user=bb" -f sql/tmp_shared_schema.sql`（DSN 取值等价 `sed -n 's/^BB_PG_DSN=//p' <deploy-dir>/pg.env`，**绝不 bash source 它**）。
- 服务：更新龙虾 `<deploy-dir>/blackboard_svc.py` 后 `systemctl restart agent-team-blackboard`；用 `/healthz` 自报的 `version` 确认跑的是新代码（不是旧进程）。
- **重启 9940 不影响公网看板**：公网链路是 隧道 → `127.0.0.1:9942`(view) → 上游 9940，9940 瞬断几秒，view 会 502 一下。改动窗口选低峰，做完立刻复验看板。
