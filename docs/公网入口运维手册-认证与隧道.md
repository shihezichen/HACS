# 公网入口运维手册（认证 + Cloudflare 隧道）

> 适用：龙虾（lobster）上的只读看板 9941 要对外网开放（刚哥手机在外网看 / 可能给其他人看）。
> 铁律：**先认证，后暴露**。认证未验收通过前，不开任何公网入口。

## 一、组件与边界

```
手机/外网浏览器
   │ https（Cloudflare 真证书，无需备案、无需开端口）
   ▼
Cloudflare 边缘 ──隧道──▶ cloudflared（跑在龙虾本机，出站连接，无入站端口）
                              │ http://127.0.0.1:9941
                              ▼
                       blackboard_view.py（public 模式：一律要求登录）
                              │ 带 token 转发
                              ▼
                       blackboard_svc.py 9940（只读，tailnet）
                              ▼
                       PostgreSQL 16（9950，仅 127.0.0.1）
```

**为什么 `127.0.0.1` 在 public 模式下不免登录**：cloudflared 就在本机以 `127.0.0.1`
回连服务；一旦"本机免登录"，公网请求就跟着免检 → 等于开后门。
免登录白名单**只认 tailnet 段 `<tailnet-cidr>`**（内部 Agent 走 tailnet IP 直接检索，不受影响）。

## 二、认证（`view_auth.py`）

```bash
# 1) 会话签名密钥（只生成一次，权限 600）
python3 <deploy-dir>/view_auth.py init-key --key-file <deploy-dir>/view-session.key

# 2) 建账号（口令走 stdin，明文永不落库/不进命令历史/不进聊天）
printf '%s' "$NEW_PASS" | python3 <deploy-dir>/view_auth.py adduser \
    --user gangge --role owner --password-stdin

# 3) 给外人建只读账号
printf '%s' "$PASS2" | python3 <deploy-dir>/view_auth.py adduser \
    --user guest1 --role viewer --password-stdin

python3 <deploy-dir>/view_auth.py list
python3 <deploy-dir>/view_auth.py audit --limit 20
python3 <deploy-dir>/view_auth.py sessions --revoke-all --user guest1   # 一键踢下线
```

角色口径：
- `viewer`（给外人）：只看 public 级内容；`internal`/`sensitive` 一律显示"存在但无权查看"；
- `member`（内部 Agent 对应的人）：可看 `internal`；
- `owner`（刚哥本人）：可看 `sensitive`（主人画像/关键信息、节点公网 IP、Agent 类型）。

## 三、隧道（Cloudflare）

**快车道（零账号，地址临时）**：
```bash
cloudflared tunnel --url http://127.0.0.1:9941 --no-autoupdate
# 输出 https://<随机>.trycloudflare.com —— 重启即换地址，只适合先验收
```

**固定域名（需要 Cloudflare 账号 + 一个域名）**：
```bash
cloudflared tunnel login                       # 浏览器授权，证书落 ~/.cloudflared/cert.pem
cloudflared tunnel create agent-team-board     # 生成 tunnel id + 凭据 json
cloudflared tunnel route dns agent-team-board board.<你的域名>
# <cloudflared-dir>/config.yml
#   tunnel: <tunnel-id>
#   credentials-file: <home>/.cloudflared/<tunnel-id>.json
#   ingress:
#     - hostname: board.<你的域名>
#       service: http://127.0.0.1:9941
#     - service: http_status:404
systemctl enable --now cloudflared             # 开机自启、断线重连
```

**systemd 单元（固定域名档）**：`/etc/systemd/system/cloudflared.service`
```
[Unit]
Description=Cloudflare Tunnel (agent-team board)
After=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/cloudflared --no-autoupdate --config <cloudflared-dir>/config.yml tunnel run
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## 四、部署形态（`deploy_auth.py`，一次跑完）

```bash
cd <repo>/agent-team
"<home>/AppData/Roaming/uv/python/cpython-3.11-windows-x86_64-none/python.exe" deploy_auth.py
```

它做 6 件事（幂等，可重复跑）：推 4 个文件 → `py_compile` → 落认证表（DDL 经 `docker exec agent-team-pg psql`，**宿主机上没有 psql**）→ 生成会话密钥（已存在则不动，避免全场掉线）→ 写两个 systemd 单元 → 重启并自检。
**两个实例是硬隔离，不要再合并**：

| 实例 | 绑定 | 模式 | 谁用 |
|---|---|---|---|
| `agent-team-blackboard-view.service` | `<host>:9941` | `--mode tailnet` | 内网 Agent，**免登录**（旧行为零回归） |
| `agent-team-blackboard-view-pub.service` | `127.0.0.1:9942` | `--mode public` | 只给 cloudflared 回连，**强制登录** |

`public` 模式的免登录白名单**只认 tailnet `<tailnet-cidr>`**；`127.0.0.1` **不在白名单**（cloudflared 就是从回环来的，放行它等于没认证）。

### 两套 IP 并用：免登录看「对端」，锁定/审计看「真实访客」
`cloudflared` 回连时**对端 IP 恒为 127.0.0.1**，于是直接拿对端 IP 记锁定会出两个问题：坏人连错 5 次就把**全体公网用户**锁 15 分钟（拒绝服务）；审计里人人都是 127.0.0.1，事后追不了责。
所以公网实例加 `--trust-proxy 127.0.0.1`（**默认空 = 谁都不信，行为与以前完全一致**）：

- **免登录白名单**：只看**对端 IP**，**永远不看头** —— 否则伪造 `CF-Connecting-IP: <tailnet-cidr>` 就能白拿内网待遇；
- **锁定键 + 审计 IP**：对端 ∈ 受信反代时用 `CF-Connecting-IP`（当 IP 字面量校验，非法/空/超长一律退回对端 IP），否则用对端 IP。

安全代价讲清楚：`CF-Connecting-IP` 由 Cloudflare 边缘写入、客户端伪造不了；但**本机上任何进程**都能直接对 9942 发这个头 —— 能起本机进程的人本来就在机器里，威胁面没有变大。真正的红线是**别把 9942 绑到 0.0.0.0 或放进 tailnet 免登录白名单**。

## 五、验收（每一项都要有实测输出，不许口头"应该可以"）

现成脚本（在龙虾上执行，口令在机上现生成、只回传 HTTP 码，不进聊天/日志）：
```bash
python accept_auth.py        # 10 项，含审计与锁定
```
10 项 = 未登录 302 → 登录页 200 → 正确口令发会话 → 带会话 200 且无公网 IP 明文/越权遮蔽 → 错误口令不建会话 → `POST /api/*` 405 → 安全六件套 → `view_audit` 有留痕 → 内网 9941 仍免登录 200 → 连错 5 次锁 15 分钟。

**两条踩过的坑，别按"直觉"改回去**：
- **「连错锁死」必须放最后跑**：锁定按**来源 IP** 记（`FAIL_MAX=5` / `FAIL_WINDOW_S=300` / `LOCK_S=900`），失败表 `view_login_failures` 是 **append-only，删不掉、没有解锁后门**（守卫触发器会回 `append-only：不允许 DELETE ... 锁定到点自然失效`）。跑完这一项，**来源 IP 约 15 分钟内登不进去**。
- 因此任何断言看到「尝试过于频繁」要判 **SKIP**（上轮锁定窗口未到点），**不是 FAIL** —— 否则窗口期内重跑会误报"认证坏了"。

单步手测（原 7 项口径，仍适用）：

1. **未登录**：`curl -I https://<公网地址>/` → `302` 到 `/login`；`/api/*` 同样 302；
2. **登录**：POST `/login` 拿 cookie → 带 cookie 访问 `/` 得 200（**v1.5 起这是 webPortal 卡片墙**，白板在 `/board`）；
3. **越权**：`viewer` 账号访问含 sensitive 的内容 → 只有"存在但无权查看"，**标题正文都不出现**；
4. **只读**：`POST /api/*` → `405`；
5. **内网不受影响**：从 tailnet IP 直接 `curl http://<host>:9941/api/sessions` 仍免登录 200；
6. **审计**：`view_auth.py audit` 能看到登录成功/失败/越权记录（表列名是 `audit_id`/`ts`，**不是** `id`/`created_at`）；
7. **暴力破解**：同 IP 5 次错口令 → 锁定 15 分钟。

### 单测
`python -m unittest tests.test_view_auth`（63 项）、`python -m unittest tests.test_blackboard_view`（152 项，含 v1.5 卡片墙 6 项）；全量 `tests.test_blackboard_view tests.test_view_auth tests.test_blackboard_svc tests.test_roundtable tests.test_rt_remind tests.test_shared_content tests.test_teamd` = **570 项**，其中 `test_rt_remind` 有 2 项在「本机存在 NATS 凭据」的机器上会失败（用例假设无凭据时 commit 必须被拒），与本手册的入口改动无关。

## 七、webPortal 首页（v1.5，2026-09-22）

把「登录进来只有白板」改成「登录进来先看到卡片墙」。改动只在 `blackboard_view.py` 一个文件：

| 路径 | v1.4 | v1.5 |
| --- | --- | --- |
| `/`、`/portal` | 白板本尊 | **webPortal 卡片墙**（只做入口，不渲染任何黑板数据） |
| `/board` | 404 | **白板本尊**（原页面，一字未改） |
| `/?<任意查询串>` | 白板 | `302 → /board`（白板时代的老书签不断） |

卡片清单在 `blackboard_view.py` 的 `PORTAL_CARDS` 里，改那一处就能加减卡片：

- **团队看板**（`ready=True`）→ `/board`，同源同登录态，点进去就是白板/会议/共享内容/跟踪；
- **人机对话台**（`ready=False`）→ `https://chat.example.com/`。

纪律没有松动：门禁在 `_route()` 的最前面，**未登录访问 `/`、`/board`、`/portal` 一律还是 302 → `/login`**；写方法仍然 405（`DELETE /` 也是 405）；卡片墙不 fetch 任何 `/api/*`。

回滚：`cp -p <deploy-dir>/blackboard_view.py.bak-20260922-120333-preportal <deploy-dir>/blackboard_view.py && systemctl restart agent-team-blackboard-view-pub agent-team-blackboard-view`。

### 「人机对话台」那张卡为什么先是灰的（待办，别漏）

对话台（`chat_svc.py`，龙虾 `<host>:9980`）目前**只有 tailnet 入口，没有公网入口**，而且不能照搬看板的做法：

1. `chat_svc.py` **没有 `--mode public`**，也没挂 `/login` 页面 —— 它只认 `bbview_session` cookie 或 tailnet 对端 IP；
2. `bbview_session` 是 **host-only cookie（`Path=/`、没有 `Domain`）** —— 在 `board.example.com` 登录拿到的会话，浏览器不会带到 `chat.example.com`；
3. 隧道若直接指向 `http://<host>:9980`，对端 IP 落在 `<tailnet-cidr>` → 命中 tailnet 免登录 → **等于把 owner 权限开给全世界**，绝对不能这么挂。

要点亮这张卡：先给对话台做「公网认证实例」（学 9942 那条路：本机回环监听 + `--mode public` 强制登录），再把 `chat.example.com` 加进 `<cloudflared-dir>/config.yml` 的 ingress 并用 `cloudflared tunnel route dns` 建记录，最后把 `PORTAL_CARDS` 里那张卡的 `ready` 改成 `True`。

> **2026-09-22 已办**：上面这三步都做完了，见第八节。注意实测结论与推测有出入 ——
> `chat_svc.py` 虽然**没有** `--mode public` 这个开关，但它的 `_resolve_visitor()`
> 本来就按同一口径写死：「免登录白名单只认 tailnet 段，**127.0.0.1 不在名单里**」。
> 所以**绑回环 + 走 cloudflared** 这一条路天然就是强制登录，不需要新增 mode 参数；
> 反而必须警惕的是**绝不能**把 ingress 指向 `<host>:9980`（tailnet 免登录）。

| 公网域名 | 指到 | 说明 |
