## 0. 它在阶段5 里的位置

阶段5 的目标：把「成员入网」从**人工改 NATS 配置**变成**按档案 + 探针自动生成**。
顺序不可颠倒 —— **先量、再冻结、最后才生成**：

1. **本刀（第一刀）**：只读对账，把「现网究竟长什么样」量出来并冻结成基线。**不动 NATS、不改任何运行件。**
2. 后续刀：拿基线里的非零项当待办清单去消（吊销僵尸凭据 / 收敛遗留中枢 / 路由去重）。
3. 收口刀：期望矩阵改由「档案 + 探针」推导，生成器写配置 —— 到那时本对账器就是它的**验收门禁**。

## 1. 名词与真源（谁是权威）

| 名词 | 定义 | 真源 |
|---|---|---|
| **中枢** | 跑 v2 nats-server 的节点 | 本件常量 `HUBS_DEFAULT`（**按节点名**声明，不写 IP）|
| **名册** | 中枢 `nats.conf` 里 `authorization.users` 的规范形（用户集 + 口令）| 中枢配置文件本身（本刀不引入新真源）|
| **角色模板** | 某用户「应得」的 `permissions` 串 | L1 `agent-team/gen_nats_conf.py :: perm_list(user)` —— **唯一出处**，本件不另抄 |
| **落地** | 该成员的凭据真的存在于某处 | `<conf_dir>/<member>.pass` 或 `<runtime_dir>/nats-<member>.pass` |
| **活连接** | 此刻真的连着中枢的客户端 | 中枢监控口 `/connz` |

**为什么名册真源就是配置文件本身**：阶段5 的第一刀不允许引入「第二份真相」——
一旦本件自己维护一份名册副本，它和中枢配置谁对谁错立刻变成新的争论点。
本刀把「配置即真相」如实量出来；等第二刀再让档案 + 探针成为真源，那时对账器的角色从「发现真相」变成「验收生成结果」。

## 2. 六项检查（键名与判定口径冻结）

| 键 | 检查 | 差异条件（出现即记一条 finding）|
|---|---|---|
| `M1` | 中枢间用户/口令矩阵一致 | 两中枢 (user → 口令) 集合不相等；逐条记 `user_missing` / `user_extra` / `password_diverged` |
| `M2` | 权限形状合规 | 某用户现网 `permissions` 串 **≠** `perm_list(user)` 逐字符（角色模板漂移 / 手工改过配置）|
| `M3` | 凭据落地一致 | 某机上的 `<member>.pass` 内容 **≠** 名册里该 member 的口令（`cred_mismatch`）；或存在名册外的 `*.pass` 孤儿文件（`cred_orphan`）|
| `M4` | 名册成员落地覆盖 | 名册里有该成员，但**既无凭据文件、又无活连接** → `zombie_credential`（吊销候选）|
| `M5` | 活连接 ⊆ 名册 | `/connz` 里的客户端（按 `authorized_user`，缺失则回退客户端名 `teamd-<member>`）落在名册外 → `outside_roster`（**硬违规**，说明有未登记的入网口）|
| `M6` | 遗留中枢与路由重复 | `legacy_hub`：某节点上跑着**非 v2 形状**的 nats-server（整份配置**没有 `permissions` 块** = 全权，或端口不在 v2 面内）· `duplicate_route`：集群 `/routez` 条目数 > 2 或存在 idle > 1h 的陈旧路由 |

**M6 为什么要算「遗留中枢」而不是忽略**：全权凭据是这套系统里权限模型唯一的洞 ——
它对 `permissions` 的检查天然免疫（M2 只审中枢，不审非中枢上的旧配置文件）。
你不点名它，它就永远不在雷达上。

## 3. 采集面（两条，产出同一形状的 artifacts）

```
--live                       经 ssh 到各中枢真采：cat <conf> / ls -1 <conf_dir> / curl -s http://127.0.0.1:<mon>/connz|routez
--fixtures <dir>             从冻结夹具读同一形状（供装置离线、确定性复跑）
```

**只读铁律**：远端命令面**只有** `cat` / `ls -1` / `curl -s`（GET）。
本件不含任何远端写操作、不重启单元、不改 `nats.conf`；`--live` 全程可随时 Ctrl-C，不留痕。

**口令一个字节都不出门**：采集器把口令**当场**换成 `sha256` 摘要，明文连 artifacts 都进不去；
出口（文本 / `--json` / 基线文件）只允许 `{member, location, sha256_8}`。

## 4. 输出、退出码与基线冻结

```
--live [--json] [--out F]            采集 + 报告（不比对）
--live --write-baseline F            把本次结果冻结成基线
--check [--baseline F]               采集并与冻结基线**逐项比**（默认基线路径见上）
```

| 退出码 | 含义 |
|---|---|
| `0` | `--check`：与冻结基线**逐项一致**（含「基线里记过的已知非零项、本次还是那几条」）|
| `1` | `--check`：**有漂移** —— 要么冒出新的 finding，要么基线里记过的 finding **消失了** |
| `2` | 采集失败（ssh 不通 / 配置文件读不到 / `/connz` 无应答）—— **不许退化成 0** |

**「消失也算漂移」是刻意的**：基线不是「容忍清单」，是**冻结的现状**。
将来吊销了 `bbgw`，基线里那条 `M4` 会立刻报「消失」并催你更新基线 ——
于是每一次放宽都必须留一次过账痕迹，从机制上堵死「悄悄把红的改成绿的」。

### 4.1 比的是「判据身份」，不是整条 JSON（刀28 修订）

`--check` 逐项比的是**发现项的判据身份** —— 哪一项检查 / 哪一类违规 / 落在哪个对象上 ——
把「同一裁决下会自己随时间漂移的**观测量**」递归摘出（`VOLATILE_KEYS`）。

| 登记在 `VOLATILE_KEYS` 的键 | 为什么它是观测量 |
|---|---|
| `stale_routes` | 该计数由**墙钟**决定（idle 是否越过 `STALE_IDLE_SECONDS`）：NATS 每次重启后路由 idle 归零、约 1 小时后计数**必**由 0 变正。刀26 重启中枢后，基线（stale 0）与现场（stale 2）只差这个数 → `--check` **每轮假红**（刀28 实测 rc=1，诊断行是同一裁决的「新增 + 消失」成对出现）。判据本身是布尔的「是否存在陈旧路由」，计数只是给人看的观测值。 |

**登记口径（硬约束）**：
- **判据的输入量不进这张表** —— 例：`num_routes > 2` 是 `duplicate_route` 的触发条件之一，所以 `num_routes`
  **必须留在身份里**：它一变（4 → 8）就该报漂移（装置 D 段 `nonobs_field_red` 格钉住这一点）。
- **不许拿这张表消红**：登记一个键名 = 声明「它不进判据身份」，必须**同时**在 §4.2 留一次记录。
- **裁决本身的增删照旧报漂移**：「消失也算漂移」的双向严格**一点没削**
  （装置 D 段 `verdict_gone_red` / `verdict_new_red` 钉住，`--negative` 负控同步覆盖）。

## 7. 运维与回滚

- **回滚**：本件是**只读巡检件、不部署到任何节点**（`tools/` 不进部署表），
  回滚 = `git revert` 本刀的提交，节点侧零动作、零重启。
- **日常跑法**（每次动 NATS 配置前后各跑一次）：
  ```
  cd /d/Work/多Agent相互协作
  python tools/nats_membership_audit.py --check          # 期望 rc=0（与冻结基线一致）
  python tools/nats_membership_audit.py --live --json    # 人读 / 机读全量结果
  ```
- **改基线的唯一正当理由**：确实消掉或新增了一条 finding（**或**按 §4.1 的登记口径动过身份表）。
  两种都要在 §4.2 留一行过账；**身份表只许把「钟」摘出身份，判据一条都不许放宽**。
  改完必须在台账「本次变更」里写清**哪一条、为什么**，否则下次漂移就再也追不回来。
- **红线**：不许为了让 `--check` 回 0 而放宽采样口径（例如把 `authorized_user` 缺失时静默跳过 M5、
  或把 `num_routes` 的陈旧条目当"正常"过滤掉）。口径要改，就连同装置与台账一起改，并说明理由。
