## 三、本轮踩掉的坑（都是真缺陷，已修）

1. **NATS 权限白名单漏 `_INBOX.>` 发布权** → request/reply 的应答被服务端静默拒（只回 `-ERR`），表现为「点名永远超时」。修：白名单补 `_INBOX.>`；探针改为把 `-ERR` 打进失败明细（**服务端"静默拒绝"这类坑，必须让客户端看得见**）。
2. **`MSG` 行字段错位**：有 reply subject 时是 `MSG <subj> <sid> <reply> <size>`，size 在最后；按固定位次取 size 会 ValueError 直接打死收包线程（表现为"连上了但永不收消息"）。
3. **把 stdin EOF 当退出信号** → 计划任务/systemd 下 stdin 是 `/dev/null`，服务一起就自杀。修：默认不看 stdin，只有 `--watch-stdin`（交互调试）才看。
4. **配置/脚本 CRLF** → Linux bash/systemd 直接崩（`$'\r': command not found`、`Invalid unit name "…\x0d"`）。修：写远端文件一律 `newline="\n"`。
5. **XML 任务模板里的 `\n`/`\a`**：Python 非原始字符串把 `<home>\agent-team\nats-...` 的 `\n` 变成真换行 → 任务 XML 格式错误。修：模板用 `r"""`。
6. **计数器 API 想当然**：`Counters` 只有 `snapshot()`，写 `counters.get(...)` 编译能过、跑起来才炸 → 用 `snapshot().get(...)`。

## 四、两条要记住的部署纪律

1. **笔记本跑的是部署副本**：`<home>\agent-team\teamd.py`、`<home>\agent-team\a2a_svc.py`（不是 `<repo>\agent-team\` 的源文件）。
   改完源码**必须同步副本**，否则改了没效果、服务照旧跑旧代码。
2. **跨平台文件必须 LF**：从 Windows 往 Linux 下发脚本/单元/口令文件，一律显式 LF，否则一律踩坑。

### 2. codex 后端修复（原本就是坏的）

- 修复：同 PiAgent/ClaudeCode 套路 —— `cli_backend.py` 增加 `codex/default`（spawn `codex exec`），codex 后端改指 `127.0.0.1:9970`。真跑 11.7s 拿到 CLI 回复；笔记本 `agents.json` 已改，A2A 已重启。

### 3. 事故复盘（我方操作失误，已修复）
- 我为重启 teamd 用了 `Stop-Process -Name pythonw` **通杀**，把同在 pythonw 下运行的 **A2A 服务一起杀停**，且它不会自愈（任务停在 Ready）。
- 修复：按端口定位 PID（`netstat -ano`）→ 精确 kill → 重起任务。
- **纪律**：本机 a2a / teamd / cli_backend 都是 pythonw 宿主，**只能按端口找 PID 杀，禁止按进程名通杀**。
