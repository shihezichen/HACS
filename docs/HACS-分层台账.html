一、这份台账怎么用

本文件是《HACS 分层规划》的阶段 0 产出，是层归属与门禁基线的唯一权威版本。 规划文档（docs/HACS-分层规划-handoff.html）回答「该怎么分、为什么这么分」；本台账回答 「现在每个件实际站在哪一层、依赖谁、踩了哪条判据、怎么复查」。动结构之前先对台账， 偏离先升版本再动码。

1.1 三个口径

  • 层归属是人判的，不是推的。判断法则沿用规划文档：通信层四节点对等、业务层中枢独有。 一个件若同时干两层的活，台账里记两个层并打 拆分点， 不为它硬凑一个层。
  • 数字全部来自实测，可复跑：件数/行数 来自 wc -l；门禁五项来自 python tools/check_layers.py；进程与启动方式来自本机进程与计划任务实查。 标注 会漂移 的，落地前复核。
  • 提示级 vs 硬级。只有「依赖方向」是硬门禁（退出码 1）。业务词、宿主硬编码、存储句柄 是提示级：它们的命中必须人判（注释里提到「会话」不算越层，真去读别人库算）。 退出码 2 = 源码树守卫：源文件缺失超过一成时判「查不了」，不给假绿灯 （对外仓里只有层归属表、没有源码，跑出来会是「件数齐全、零违规」——那是假象）。

三、依赖方向实测（门禁检查 1）

结论：现有 import 图与五层方向一致 —— 零反向依赖。 这不代表解耦没问题，而是说明耦合不长在「谁 import 谁」上。真正的越层是三处： 语义越层（业务词长在通行层）、句柄越层（通行/适配件直读别人的库）、配置静态（改动靠改文件+重启）。 后两处见第四、七节。

3.1 判据与门禁规则

  • 允许方向：L4 → L3 → L2 → L1 → L0（上层依赖下层）；同层可互依； 横切 X 可被任意层引用；工具面 T 不受限（不属运行路径）。
  • 组合根 C（进程入口装配）排在方向序列最前：C 可 import 任意层，任何层不得 import C。 判据逻辑无需特判 —— C 的 rank 最小，rank[src] <= rank[dst] 天然成立/天然违规。 它的用途是给「反向依赖」一个合法出口：把注入动作放进进程入口，而不是让下层去 import 上层。
  • 反向依赖（下层 import 上层）= 硬违规，退出码 1，必须改。
  • 工具面缺席会让结果失真：ledger_patrol.py 这类巡检件 import 域件是正常的， 把它当运行件就会报假违规。

6.4 七条硬约束（逐条可校验）

#约束怎么校验
1私钥永不出机：成员本机生成密钥对，只上报公钥注册请求体里搜不到私钥字段；抓包/日志里无私钥头标记
2数据面与控制面分离：控制面不可用时，已在网成员通信不受影响停掉注册服务，跑一轮既有成员的点对点与群发，应全通
3幂等注册：同 (成员标识, 公钥) 重复申请返回同一身份连发两次申请，比对受理号与最终签发结果一致
4授权与登记分离：登记 = 身份落库；授权 = 通道侧按角色模板放行登记后未授权时，通道应拒绝其连接（而非接受后不投递）
5吊销即时生效于新连接，已建立连接在下一轮重连时失效吊销后立刻发起重连，应被拒；旧连接的下一条消息应失败
6引导包一次性：过期/重复取用均拒绝同一包连取两次，第二次应拒
7不新造身份体系：管理员鉴权复用横切身份实现管理端点不出现第二套账号表；权限判定走既有角色

6.5 与现有件的对位（不用从零设计）

  • 角色模板的来源已有现成实现：gen_nats_conf.py 现在就在为每个成员生成 「只能发自己的心跳、收则放开」的权限白名单。动态化 = 把这套生成逻辑从「部署时写进配置」 搬到「注册时按需签发」，模板形状照抄，不用重新发明。
  • 多成员托管已是既成事实：本机一个守护进程托管 5 个成员身份（见第七节）， 所以入网服务要按成员粒度设计，不是按进程粒度 —— 否则同机的 5 个身份没法各入各的网。
  • 名册真源需要一次迁移：现在名册靠订阅心跳动态收集；目标的 /members 是登记库 + 心跳的合成视图，不能两套并存，否则「谁在网」有两个答案。
  • 通道侧需要一次性配置：签发侧需要通道服务端开一次「外部授权」开关并指向本服务 —— 实测通道服务端版本 2.14.5，满足外部授权方案的最低版本要求， 这条路在现网走得通，不必先升级（探测方式：只读连客户端口读服务端握手信息；日期 2026-09-25）。

6.6 失败模式与兜底

六种失败模式（引导包被截获 / 注册服务挂 / 伪装注册 / 重复注册 / 授权服务故障 / 版本漂移） 的逐条兜底见规划文档 6.2 节，本草案不重复。此处只加一条与台账相关的：version 漂移必须可观测 —— 台账登记每个在网成员的客户端版本，注册服务拒收低于最低兼容版本的申请，并写审计。

7.3 为什么「重启会掐断别人」

因为一个守护进程托管 5 个成员身份：为了给第 6 个成员加凭据而重启， 会把已经在网的 4 个成员的通道一起断掉。所以静态入网不只是「麻烦」—— 它把新增成员的代价转嫁给了存量成员。这一条是规划文档把它列为「第四处最痛耦合」的实证依据， 也是阶段 5 优先级的来源。
