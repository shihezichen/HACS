## 1. 全局硬纪律（每个用例都要能测到，评审强制）

- **D1 `from` 只能由 token 反查**，绝不采信 payload 里的 `from`。
  依据：`a2a_svc.py:201` 已确立此纪律；`msg_log.from_member` 若采信 payload = 把修好的漏洞重新引入。
  用例：`MSG-07`。
- **D2 时间戳一律由 PG `now()` 生成**，不许用收件方本地时钟（时钟漂移会让 TTL 乱）。
  用例：`MSG-08`。
- **D3 单一过期权威**：正文过期归 tmp box，**消息状态**过期归 msg_log。`msg_log` **不得**再放一份 `content_ref` 的 TTL。
  用例：`MSG-09`。
- **D4 不静默重跑**：`processing` 超时**不得**被 sweep 自动重投（会造成重复副作用：重复下达任务/重复扣费）。转 `stalled` + 告警，人工决定。
  用例：`MSG-10`。
- **D5 `expired` 不丢数据**：行保留、可见、可从查询接口读到，并通知发送方，不是安静消失（否则违背「写操作逐条留痕」红线）。用例：`MSG-11`。
- **D6 拒收 ≠ 丢弃**：队列满时回 `busy`，但消息**已在库**，等对方有空补投。用例：`Q-05`。

## 2. P0-A：`say` 默认派生 session_id

### 契约
- `cmd_say` 现在：`if args.session_id: envelope["session_id"] = ...` → **不带就完全不传**（病根）。
- 改为：`session_id = args.session_id or derive_default_session(from_member, target, now)`。
- **派生规则（定死）**：`"say-%s-%s-%s" % (from_member, target, YYYYMMDDHH)`
  - 按**小时**分桶：同一小时内 A→B 的连续对话 = 同一会话（多轮上下文成立）。
  - 跨小时自动滚新桶：避免后端上下文无限堆积（openclaw 现已 38k/120k，纯固定键会顶到窗口上限）。
  - 不引入对中枢的依赖（成员机只准两文件，且零 RPC），可离线单测。
- 优先级：`--session-id` 显式指定 **>** 默认派生。
- 新增 `--new-session`：强制生成新会话（`say-<from>-<target>-<ts>-<4位随机>`），用于「我不想接上文」。
- **函数签名（实现按此，便于单测）**：
  ```python
  def derive_default_session(from_member, target, now=None):
      # type: (str, str, Optional[float]) -> str
      """不带 --session-id 时的默认会话键：按小时分桶的稳定派生。"""
  ```

### 用例
| 编号 | 场景 | 预期 |
|---|---|---|
| `SESS-01` | 不带 `--session-id` 调用 `cmd_say` | 信封**必须含** `session_id` 字段（非空） |
| `SESS-02` | 同一小时、同一 (from,target) 连调两次 | 两次 `session_id` **完全相同**（多轮成立） |
| `SESS-03` | 跨小时（`now` 注入 +3600s） | `session_id` **不同**（自动滚桶） |
| `SESS-04` | 不同 target | `session_id` 不同 |
| `SESS-05` | 显式 `--session-id my-sid` | 用 `my-sid`，不被默认派生覆盖 |
| `SESS-06` | `--new-session` | 生成新键，且与默认派生键**不同**；两次 `--new-session` 互不相同 |
| `SESS-07` | `--new-session` 与 `--session-id` 同时给 | 报错退出（参数互斥），退出码 2 |
| `SESS-08` | 派生键格式 | 匹配 `^say-.+-.+-[0-9]{10}$`，不含空格/中文 |
| `SESS-09` | `meet` 行为**不受影响** | `cmd_meet` 仍用 `meet-<ts>-<rand>`，回归用例 |

### 端到端（真跑，非单测）
| 编号 | 场景 | 预期 |
|---|---|---|
| `SESS-E2E-01` | 不带 `--session-id` 连发两轮，第二轮问「上一句数字」 | **答对**（对照实验已证：带 session 则记得） |

## 3. P0-B：codex 会话映射落盘

### 契约
- 现状：`cli_backend.py:137` `Runtime.codex_sessions = {}`（**纯内存**），`411/444` 读写它 → **进程重启即静默失忆**。
- 改为：映射持久化到 JSON 文件，原子写（写临时文件 + `os.replace`）。
- 路径：`<workdir>/.codex_sessions.json`（可由环境变量 `CODEX_SESSIONS_FILE` 覆盖，便于测试注入）。
- 结构：`{"<session_key>": {"sid": "<codex session id>", "updated_at": <epoch>}}`
- 读：进程启动/首次使用时懒加载；写：每次 `setdefault` 成功后立即落盘。
- **失败不许吞**：落盘失败要 `log` 警告，但**不阻断**本次请求（可用性优先）。
- `Runtime.codex_sessions` 保留为内存缓存，外面包一层读写函数。
- **`claude_sessions`/`pi` 不在本档范围**（它们用稳定派生/uuid5，重启可续）。

### 用例
| 编号 | 场景 | 预期 |

| `CX-01` | 首次写映射 | 文件生成，内容含该 key→sid |
| `CX-02` | 重建 Runtime（模拟重启）后读 | **读回**同一 sid（核心：不再静默失忆） |
| `CX-03` | 文件不存在 | 不抛异常，视为空映射 |

| `CX-07` | 映射更新（同 key 新 sid） | 覆盖旧值 |
| `CX-08` | 与其他 agent（pi/claude）隔离 | 不影响它们的会话路径 |

## 4. P1-A：有界队列 + worker 池 + `busy` 拒收

### 契约
- 现状：`teamd.py:686` 每消息 `threading.Thread(...)` **无上限**；全仓 `Semaphore/Queue/ThreadPool/max_workers` **零命中**。
- 改为：`on_nats_message` → **有界队列**（`queue.Queue(maxsize=N)`）→ 固定 worker 池（M 个）。
- 默认：`N=64`、`M=4`，均可由 config/参数覆盖（测试注入小值，如 N=2/M=1）。
- **队列满**：立即回 `{"ok": false, "error": "busy", "retry_after_ms": <int>}`，**不阻塞、不静默排队**。退出码语义对齐现有 `timeout`。
- **per-member 闸门**：一个 agent 的积压不得堵住其他 agent（至少：队列/计数按 member 分或全局但可观测）。
- 必须保留现有语义：reader 回调**立刻返回**（否则心跳都收不到）。
- 关闭时 drain：stop 时把队列里剩余任务处理完或明确标记未处理。

### 用例
| 编号 | 场景 | 预期 |
|---|---|---|
| `Q-01` | 并发投 N+5 条、worker=1、处理慢 | 前 N 条入队，后 5 条收 `busy` |
| `Q-02` | 空队列 | 不报错；worker 待命 |
| `Q-03` | FIFO 顺序 | 处理顺序 = 入队顺序 |
| `Q-04` | 队列满时回包**不阻塞** | 回 `busy` 在毫秒级（<100ms），不是干等 |
| `Q-05` | `busy` 拒收后 | 发送方可从 msg_log 查到该消息仍在（拒收≠丢弃，依赖 P1-B） |
| `Q-06` | 一个 member 打满队列 | 其他 member 仍能正常处理 |
| `Q-07` | worker 抛异常 | worker 不死，继续处理后续；异常被记录 |
| `Q-08` | reader 回调耗时 | 回调**立刻返回**（<50ms），不因队列满而阻塞 |
| `Q-09` | stop 时 | 队列 drain 或明确标记，无静默丢失 |
| `Q-10` | `healthz`/`varz` 暴露 | 能看到 `queue_depth`、`workers`、`busy_count` |

## 5. P1-B：`msg_log` 落库=送达

### 表 DDL（`sql/msg_log_schema.sql`，幂等）
```
msg_id        text PK           -- 发送方生成，幂等键
from_member   text NOT NULL     -- ★ 由 token 反查（D1），不采信 payload
to_member     text NOT NULL
session_id    text              -- 可空；挂会话
subject       text
body          text              -- 短正文；长正文走 content_ref
content_ref   text              -- tmp box id（其 TTL 归 tmp box，D3）
state         text NOT NULL     -- queued|processing|done|failed|stalled|expired
seq           bigserial         -- ★ 回放排序权威（不用 msg_id，评审指出）
attempts      int DEFAULT 0
created_at    timestamptz DEFAULT now()   -- ★ PG 单点（D2）
delivered_at  timestamptz
started_at    timestamptz
finished_at   timestamptz
expires_at    timestamptz       -- 消息状态过期（不是正文 TTL）
last_error    text
```
- 索引：`(to_member, state)`、`(session_id, seq)`、`(created_at DESC)`。
- CHECK 约束限定 `state` 值域。
- 守卫：**只允许单向状态推进**（queued→processing→done/failed/stalled/expired），回退/抹人拒绝（复用 tmp box 守卫风格）。

### 状态机
```
queued ──落库成功即「送达」──> (等待投递后端)
  ├─> processing ──> done
  │                └─> failed（后端明确失败）
  │                └─> stalled（★ 超时：不自动重投，告警，D4）
  └─> expired（★ queued 超 TTL 未投递；行保留可见，D5）
```

### 接口
- `POST /msg`：落库（**发送方或收件方 teamd 都可用**），返回 `msg_id` + `state`。
  - **落库成功 = 送达**（这是权威判据，替代 ACK 握手）。
- `GET /msg/<id>`：查状态（任意成员可查自己的收/发）。
- `GET /msg?to=<me>&state=queued`：补拉用（P2-B）。
- `POST /msg/<id>/state`：推进状态（收件方 backend 完成后回写）。

### 用例
| 编号 | 场景 | 预期 |
|---|---|---|
| `MSG-01` | 落库成功 | 返回 `state=queued`，且 GET 可读到（**落库=送达**） |
| `MSG-02` | 同 `msg_id` 重复落库 | 不产生第二行（幂等），返回同一条 |
| `MSG-03` | 状态推进 | `queued→processing→done` 合法，`finished_at` 落上 |
| `MSG-04` | 非法推进（回退） | 拒绝（退出码/HTTP 4xx），行不变 |
| `MSG-05` | 未知 msg_id 查询 | 404 |
| `MSG-06` | 非本人查询他人消息 | 403 |
| `MSG-07` | **payload 伪造 `from`** | 落库的 `from_member` = **token 反查身份**，不是 payload（D1，评审强制） |
| `MSG-08` | **客户端传 `created_at`** | 被忽略，库里 = PG `now()`（D2） |
| `MSG-09` | schema 检查 | `msg_log` **无** content_ref 的 TTL 字段（D3，单一过期权威） |
| `MSG-10` | `processing` 超时 sweep | 转 `stalled` + 记录，**不回到 queued**、**不自动重投**（D4） |
| `MSG-11` | `queued` 超 TTL | 转 `expired`，**行保留且可查**，通知发送方（D5） |
| `MSG-12` | 长正文 | body 留摘要 + `content_ref` 指向 tmp box |
| `MSG-13` | DDL 幂等 | 重复执行 schema 无报错 |
| `MSG-14` | 守卫拒 DELETE/TRUNCATE | 拒绝（对齐 tmp box 风格） |
| `MSG-15` | `(to_member, state)` 查询 | 走索引，返回补拉所需集合 |

## 7. P2-A：服务端回放（加固，非核心）

### 契约
- 每次下发前，把该 `session_id` 的**最近 N 轮**拼进 prompt 前缀（N 可配，默认取小值如 6，控制 token）。
- **排序必须用 `seq`（PG BIGSERIAL）**，**不得**用 `msg_id`（评审：单调 ≠ 顺序，跨发送方会乱序）。
- **注入边界**：拼进去的历史要**明确标记为历史**（不是当前指令），避免 agent 把旧话当新指令。
- 回放**只读**，不改历史；历史缺失（表无记录）时**不编造**，明确标注「无历史」。
- 目的是**加固**：抗重启（后端记忆丢了库里还有）、可审计、跨后端一致。

### 用例
| 编号 | 场景 | 预期 |
|---|---|---|
| `RP-01` | 有 5 轮历史，N=2 | 只拼最近 2 轮 |
| `RP-02` | 排序 | 按 `seq` 升序，非 `msg_id` |
| `RP-03` | 无历史 | 不编造，前缀为空或标注「无历史」 |
| `RP-04` | 历史标记 | 明确的「[历史]」边界标记，与当前指令可区分 |
| `RP-05` | 空 session_id | 不回放（退化为单轮） |
| `RP-06` | N 超配 | 不因历史过长炸上下文（有上限截断） |
| `RP-07` | 只读 | 回放不改动 `msg_log`/`session_turns` 任何行 |

## 8. P2-B：离线补拉

### 契约
- teamd 启动时 + 周期（如 60s）→ `GET /msg?to=<me>&state=queued` → 逐条**经队列**投递后端 → 推进状态。
- **必须走 P1-A 的队列**：否则上线瞬间把积压全投，打爆后端（评审：这是最容易炸的场景）。
- `processing` 的**不重投**（D4）；`stalled` 的通知人工。
- 补拉幂等：重复投递靠 `msg_id` 去重。

### 用例
| 编号 | 场景 | 预期 |
|---|---|---|
| `BF-01` | 启动时有 3 条 queued | 全部投递，状态推进 |
| `BF-02` | 积压 100 条、队列 64 | 前 64 入队，其余留在 queued（不丢），下轮继续 |
| `BF-03` | 补拉时 `processing` 的行 | **不重投** |
| `BF-04` | 重复补拉 | 幂等，不产生重复副作用 |
| `BF-05` | 后端全挂 | 不无限重试；按退避 + 最终 `stalled` |
| `BF-06` | 补拉不影响在线流量 | 在线消息优先（或至少不被饿死） |

## 10. 明确不做（评审砍掉的）

- 发送方 outbox 表（发送方是短命 CLI，配 outbox 等于要求常驻，违背「成员机只准两文件」红线）→ 用 `msg_id` + 查询替代。
- `msg_log` 里复制一份正文 TTL（D3）。
- 指数退避多档（短命进程活不过几十秒）→ 一次短超时 + 一次重试 + 查询。
- NATS JetStream（只保证投递给订阅者、不保证业务处理成功；且会变成第二真相源）。
